# We draw every pixel on every platform

Every platform is a target, so the framework draws its own UI everywhere instead of handing it to native widgets or, on the web, the browser DOM; this keeps one renderer, one layout model and one text measurement, so an app looks and behaves the same on each. Flutter made the same call on the web and removed its DOM-based HTML renderer as "complex, underperforming, and limited in graphical expressivity" (https://github.com/flutter/flutter/issues/145954). How the web build reaches the DOM for accessibility and text input (a hidden DOM layer beside the canvas, or a DOM backend) is decided when web work starts; until then the core keeps a semantics tree with a stable id per node and puts text input behind the platform trait, so neither option is closed off.
